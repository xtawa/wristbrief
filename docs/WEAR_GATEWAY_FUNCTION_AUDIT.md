# Wear + gateway function audit (2026-10-01)

Scope: every Wear (`app/`) feature path and the gateway (`gateway/`) paths it depends on, checked against the
code on branch `feat/library-discovery-ux` (PR12, base `d695813`). This was a static read of the code plus
gateway unit tests. **No Wear feature is claimed production-ready here.** "Code + tests" means
logic exists and has unit/instrumented tests. "Configured runtime" means a deployed gateway, credentials,
providers and a paired phone/watch were actually used. That second level was **not** reached for any row.

Evidence boundaries:
- Gradle was not run (per instruction). None of the Wear changes below has been compiled or executed here. Kotlin/R references, the new unit tests and the new instrumented test must be confirmed by CI (`:app:testDebugUnitTest`, `:app:connectedDebugAndroidTest`). EN/zh string-key parity was checked by script, and both XML files parse.
- Gateway: `vitest` under Node 22 (`npx node@22`, since the system Node 20 has no `node:sqlite`) passed for
  `src/admin/adminSmtpTest.test.ts` and `server/audio.test.ts` (31/31). An earlier full-suite log
  (`gateway-node22-verification.log`) recorded 378/380 passing. The two failures were the SMTP timestamp flake (fixed below) and
  `server/audio.test.ts > releases the reservation when the provider fails mid-transcription`, which timed out at 5 s under full parallel load.
  That test passes on its own, so this audit treats it as a load/timeout issue, not a date defect. It is unchanged. The parent CI now installs FFmpeg and runs `npm test -- --maxWorkers=2 --testTimeout=15000`, so the ffmpeg-dependent audio tests are no longer skipped there. That configuration addresses this timeout. This audit did not observe the CI result.
- Screenshots and emulator: this audit captured none. The parent's UX-evaluation workflow
  (`.github/workflows/ux-evaluation.yml`, `scripts/capture_ux.sh`, `WearUiEvaluationTest`) has its own results. Treat
  visual claims as unverified until those artifacts are inspected.

## Remaining gaps (honest, not fixed)

Local-code items still open (lower severity, or they would need a contract the repo does not have):
1. **Wear feed pause/remove stays watch-only by design of the current contract.** The phone has no listener for Wear subscription
   changes, so a real round-trip would need a new protocol (excluded by instruction). The UI now says so and confirms removal.
2. **`wear_podcast_resume_sub` ("Resumes from your saved position")** appears on the Play button even when no progress is saved.
   The resume logic is correct; only that sub-label overstates. The fix is to read `PodcastProgressStore` in `ArticleDetailScreen` and show it only when progress > 0.
3. **Continue on phone** ignores the `RemoteActivityHelper` result future, so an unreachable phone fails silently.
4. **Continue-listening tile** opens the Inbox rather than resuming the episode.
5. **Phone progress arriving while the same episode plays on Wear** updates the store but does not seek the live player.
6. **F2 boundary:** the fence is in memory. A process restart clears it, but that also kills the playback session.
   Phone→watch progress (`WearPlaybackSyncManager.applyPhoneProgress`) for the *previous* account that arrives after the purge is not fenced.
   That would need an account id on the playback wire contract (a protocol change, not made). Items handed to the session by a non-WristBrief controller carry no tag and are attributed to the current account.
7. `WearUiReview.wearStatusLine` and the `aiFailureState` users outside the Wear UI may still contain English literals. They are not user-visible on the current screens (not confirmed for every path).

Genuinely external gates (need credentials, devices or console access; cannot be closed in code):
- Paired phone + watch: Data Layer delivery of session/subscriptions/item-state/playback, `RemoteActivityHelper`, background MediaSession, tile/complication host refresh, rotary input. This is L4.
- Gateway HTTPS deployment and `WRISTBRIEF_GATEWAY_URL` baked into the Wear build. AI provider secret/model. STT/TTS provider config. SMTP credentials in `/admin`. Google OAuth client. Play service account + RTDN Pub/Sub, Play internal track. This is L5.
- CI execution of the new unit and instrumented tests, plus inspection of the parent's screenshot artifacts.
